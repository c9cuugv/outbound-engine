# Local Dev Setup — Design Spec
**Date:** 2026-05-19  
**Branch:** device/windows  
**Goal:** Get OutboundEngine running on localhost with synthetic data, NVIDIA NIM for AI, Resend for email.

---

## Environment

| Service      | How it runs          | Port  |
|--------------|----------------------|-------|
| PostgreSQL 14 | Local (Homebrew, already running) | 5432 |
| Redis 7       | Docker (single container)         | 6379 |
| FastAPI       | Native uvicorn --reload            | 8000 |
| Celery Worker | Native (same Python venv)          | —    |
| Vite Frontend | npm run dev                        | 5173 |

Python: 3.12 · Node: 20 · Docker: 24 (infra only)

---

## Makefile Targets

```
make setup         one-time: restore deleted workers, create outbound DB,
                   create Python venv, pip install, npm install,
                   run alembic migrations, start Redis container,
                   generate JWT_SECRET into .env

make dev-api       terminal 1 — uvicorn app.main:app --reload
make dev-worker    terminal 2 — celery -A app.workers.celery_app worker -l info
make dev-frontend  terminal 3 — cd frontend && npm run dev

make seed          run scripts/seed.py against live API (httpx + Faker)
make stop          docker stop outbound-redis
```

## Deleted Workers — Recovery

`backend/app/workers/*.py` are deleted from disk but exist in git index.  
`make setup` runs `git restore backend/app/workers/` before anything else.

Workers recovered:
- `celery_app.py` — Celery instance, Redis broker
- `email_gen_tasks.py` — generate emails per lead × template
- `research_tasks.py` — scrape + AI synthesis per lead
- `send_tasks.py` — scheduled sending engine
- `reply_tasks.py` — IMAP polling + sentiment classification
- `tasks.py` — task registry / shared helpers

## Synthetic Data — `scripts/seed.py`

Standalone Python script. Uses `httpx` (async) + `Faker`. Calls the live API at `http://localhost:8000`.

### What it creates

| Entity         | Count | Notes |
|----------------|-------|-------|
| User           | 1     | `test@outbound.local` / `Test1234!` |
| Leads          | 20    | Faker B2B: name, company, domain, title, linkedin |
| Lead list      | 1     | "Synthetic Q2 List" — all 20 leads added |
| Campaign       | 1     | OutboundEngine product, NVIDIA-powered, sender = user's email |
| Email templates | 2    | Sequence step 1 (cold intro) + step 2 (follow-up, 3-day delay) |

### Output
Prints to stdout:
```
✓ User created: test@outbound.local
✓ 20 leads seeded
✓ List created: Synthetic Q2 List (id: <uuid>)
✓ Campaign created: Q2 Outreach Test (id: <uuid>)
✓ 2 templates created
Token: <JWT — paste into /docs Authorize>
```

### Dependencies
`httpx` and `faker` — both already in `backend/requirements.txt`.  
Script runs against the live API (not directly against DB) so it validates the full API layer.

## Verification Flow

1. `make setup` → no errors
2. Open 3 terminals: `make dev-api`, `make dev-worker`, `make dev-frontend`
3. `curl http://localhost:8000/health` → `{"status":"ok","database":"ok","redis":"ok","nvidia":"configured"}`
4. `make seed` → success output + JWT token
5. `http://localhost:8000/docs` → paste token → test `POST /campaigns/{id}/generate`
6. Watch Celery worker terminal → tasks received → emails generated via NVIDIA
7. `http://localhost:5173` → React UI loads, campaigns visible

## Decisions

| Decision | Choice | Reason |
|----------|--------|--------|
| AI provider | NVIDIA NIM | User has free tier; already built into codebase |
| Email provider | Resend | Simpler API than SendGrid; 3k free/month; one API key |
| Email in dev | Resend (not console) | User wants real email delivery testing |
| Redis infra | Docker only | Not installed locally; single container is lightweight |
| PostgreSQL | Local Homebrew | Already running PG14; no container overhead |
| Workers | Restore from git | Deleted locally but recoverable; needed for full pipeline |
| API iteration | Native uvicorn | Faster restarts than Docker rebuild cycle |
| Frontend | Vite dev server | Hot reload; no Docker build needed |
| Seed approach | httpx → REST API | Tests full API layer, not just DB; matches user's preference for Python scripts |
